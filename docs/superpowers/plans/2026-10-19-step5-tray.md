# Step 5 Implementation Plan: tray plugin (StatusNotifierItem host)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the tray backend as a first-party plugin that hosts `StatusNotifierItem` applets over D-Bus, listing them as cards and exposing each item's menu as a scoped child level.

**Architecture:** The tray plugin owns the D-Bus role of a `org.kde.StatusNotifierWatcher`. It registers itself, observes `ItemRegistered`/`ItemUnregistered`, and for each registered item exposes its `StatusNotifierItem` properties (title, icon, tooltip). Its menu is provided by the DBusMenu protocol (`com.canonical.dbusmenu`): the plugin implements the menu interface for the item, and the host renders the menu as a scoped child level via the item's `HasChildren`. This follows the plugin pattern: the tray owns the domain (D-Bus), the host renders schema-driven items and sub-levels.

**Tech Stack:** Go 1.27 (mise), `github.com/godbus/dbus/v5` (the one new dependency). D-Bus session bus.

**Spec:** `docs/superpowers/specs/2026-10-19-keyshell-go-architecture-design.md` (Result/control schema; Navigation and sub-queries; plugin protocol).

## Global Constraints

- Everything under `mise exec -- …` / `mise run …`; `CGO_ENABLED=0`.
- The plugin is `hot` (it must hold the watcher name regardless of summoning) and `noreap`-capable like clipboard.
- D-Bus failure degrades to an empty tray, never a crash.
- Each item has `HasChildren` when its DBusMenu offers items; the scoped child level is produced by the same `Query` with a scope.
- Tests stub the D-Bus session via godbus's in-memory/session harness where feasible; otherwise the plugin is structured so the watcher is injectable.

### Task 1: SNI watcher

**Files:**
- Create: `internal/backend/trayplugin/watcher.go` + `watcher_test.go`.

**Interfaces:**
- Produces: `Watcher` that, given a `*dbus.Conn`, requests name `org.kde.StatusNotifierWatcher`, serves the three properties (`RegisteredStatusNotifierItems`, `IsStatusNotifierHostRegistered`, `ProtocolVersion`), emits `StatusNotifierHostRegistered`, and listens for `ItemRegistered`/`ItemUnregistered`. Maintains a thread-safe item list.
- Tests: with a stub signal source, assert registration and item add/remove.

### Task 2: Item properties and menu

**Files:**
- Create: `internal/backend/trayplugin/item.go` + `item_test.go`.

**Interfaces:**
- Produces: `Item` wrapper reading `StatusNotifierItem` properties (`Title`, `IconName`, `ToolTip`), and a `Menu` accessor that implements DBusMenu (`Layout`, `GetLayout`, `Event`, `AboutToShow`) enough to enumerate a flat menu with `type: item` entries and `children-disabled` handling.
- Tests: parse a canned D-Bus property suite; a flat menu layout maps to a scoped query's items.

### Task 3: Tray plugin backend

**Files:**
- Create: `internal/backend/trayplugin/tray.go` + `tray_test.go`.
- Modify: `cmd/keyshell/main.go` — dispatch `plugin tray`; `internal/config/config.go` — default instance `{id:tray, mode:hot}`.

**Interfaces:**
- Produces: `sdk.Backend` with `Info` = `{id:tray, badge:TRAY, trigger:^, hot:true, stable_ids:true}`; `Query` returns one item per registered applet (with `HasChildren` when a menu exists); `Control`/scoped queries navigate the menu.
- Tests: with a fake watcher, assert item count and the scoped child-query shape.

### Task 4: Wire and verify

**Files:**
- Modify: `mise.toml` — `plugin:demo` notes tray.

**Interfaces:**
- Verifies: `keyshell plugin tray` handshake; the watcher claims the name on a live session bus; a real tray applet (e.g. any running applet) appears as an item.

## Self-Review

**Spec coverage:** tray = one more first-party plugin; the menu reuses the existing scoped child-level navigation (no new host code). D-Bus is the plugin's domain. The `IsStatusNotifierHostRegistered` semantics are respected (host is a watcher, not item-aware per the host flag).
**Placeholders:** none.
**Type consistency:** menu entries become items via the same `sdk.Item` shape; the scoped level uses `Scope` in `sdk.Query`.

**Deferred within step 5:** full DBusMenu recursion beyond a flat menu (submenus, check/radio toggles, icons per entry) — recorded as a follow-on. The first cut lists applets and their top-level menu items.
